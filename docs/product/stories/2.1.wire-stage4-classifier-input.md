## Story

**As a** compliance engineer running the §2 max-fidelity gate,
**I want** Stage 4 to receive the actual OCR/fused document body text as classifier input,
**so that** keyword matching operates on the real document content and the export gate clears at the correct confidence level.

---

## Acceptance Criteria

1. `ProcessingOrchestrator.ClassifyDocumentRopAsync` at line 530 populates the `ExtractedMetadata` passed to `_classifier.ClassifyAsync` with the OCR body text (from `ctx.OcrResult`) and/or the fused-source text — either via `metadata.LegalReferences` or a new dedicated body-text field — before calling the classifier.
2. `ReconciliationOrchestrator.cs:353-356` receives the identical change so that both the Athena Worker path and the Reconciliator path are consistent; the comment at `:96` ("currently unused by Stage 4") is removed or updated.
3. Case `IMSS-2023-171230` (tier-1 synthetic) classifies as `Aseguramiento` with `Confidence >= 70` when run through either orchestrator.
4. The §2 max-fidelity gate test (`MaxFidelityGateFullPipelineE2ETests`) completes Stage 5 and produces: SIRO XML output, 24-column DatosCarga xlsx, and at minimum 2 audit-trail rows.
5. `dotnet build` of the full solution produces 0 errors and 0 warnings.
6. All existing tests in `ReconciliationOrchestratorExportGateTests.cs` and `ProcessingOrchestratorTests.cs` remain green.

### Inspection Evidence

Source: `docs/planning-artifacts/remediation/CONFIDENCE-PIPELINE-DEEP-INSPECTION-2026-06-25.md` §2

**The defect (§2.2):**
```csharp
// ProcessingOrchestrator.cs:530-535
var metadata = new ExtractedMetadata { Expediente = ctx.FusionResult?.FusedExpediente };
var classResult = await _classifier.ClassifyAsync(metadata, cancellationToken);
```
`metadata.LegalReferences` is never set; the OCR body text is never attached. The classifier's `combinedText` (`FileClassifierService.cs:40-44,78`) becomes literally `"FISCALÍA ESPECIALIZADA EN MATERIA DE DERECHOS HUMANOS EXP-8217-2021 "` — none of the Level-1 keywords.

**The body text that was never passed (§2.3):**
Generator `core/legal_catalog.py:190-194,222-226` emits for `aseguramiento`:
- "se solicita el aseguramiento precautorio de las cuentas bancarias"

These words appear in the actual rendered DOCX `word/document.xml` and in the XML companion (`<TieneAseguramiento>true</TieneAseguramiento>`). With them present, the Aseguramiento branch scores 90 → `scoreDifference 80 ≥ 60` → confidence 90% → gate passes.

**The stale comment to remove (§2.2):**
`ReconciliationOrchestrator.cs:96`: *"The OCR result from the Extractor (currently unused by Stage 4…)"*

**Minimal fix framing (§2.5):**
> Thread the document body text into the classifier input (populate `metadata.LegalReferences`, or a new body-text field, with the Stage-2 OCR text and/or the fused-source text) at `ProcessingOrchestrator.cs:530` / `ReconciliationOrchestrator.cs:353`. With the body text present, the Aseguramiento branch hits score 90 → confidence **90%** → gate passes. One wiring change, no generator change, no threshold change.
