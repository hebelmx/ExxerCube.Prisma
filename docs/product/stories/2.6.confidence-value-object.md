# Story 2.6: Introduce Unified Confidence Value Object

**Status:** Draft
**Epic:** 2 - Confidence Pipeline Hardening & Re-architecture
**Stage:** Cross-Stage (Domain)
**Created:** 2026-06-25

---

## Story

**As a** pipeline architect,
**I want** a single `Confidence` value object in the Domain layer that all four pipeline stages use,
**so that** confidence values across Quality, OCR, Fusion, and Classification are on a common scale, carry provenance, and can be composed with well-defined operators.

---

## Acceptance Criteria

1. A `Confidence` record/struct is created in the Domain layer (e.g. `Domain/ValueObjects/Confidence.cs`) with: a `double Value` in `[0, 1]`; a `PipelineStage Stage` provenance tag; and static factory methods for `Zero`, `Unknown`, and `FromPercentage(double percent0To100)`.
2. `Confidence` exposes three composition operators:
   - `Min(Confidence a, Confidence b)` — returns the lower of the two values.
   - `Weighted(IReadOnlyList<(Confidence, double weight)> signals)` — returns a weighted average.
   - `Combine(IEnumerable<Confidence> signals)` — returns a simple average (for equal-weight aggregation).
3. `OCRResult` (`OCRResult.cs:16`) migrates its `float ConfidenceAvg` (0–100 scale) to a `Confidence Confidence` property; the old float field is either removed or kept as a `[Obsolete]` shim for one release cycle.
4. `FusionResult` (`FusionResult.cs:28`) migrates its `double` overall confidence to `Confidence OverallConfidence`.
5. `ClassificationResult` (`ClassificationResult.cs:28`) migrates its `int Confidence` (0–100) to `Confidence ClassificationConfidence`; the `FromPercentage` factory handles the conversion from the existing keyword-bucket int score.
6. `ImageQualityAssessment` migrates its `float Confidence` (hardcoded `0.9f` from `PolynomialImageQualityAnalyzer.cs:129`) to `Confidence QualityConfidence`.
7. All callers that read the old scalar fields are updated; build is 0/0 with `TreatWarningsAsErrors=true`.
8. A unit test suite `ConfidenceTests` covers: construction invariants (Value must be in `[0,1]`), `Min`, `Weighted`, `Combine`, and `FromPercentage` with both in-range and out-of-range inputs.
9. `ClassificationCompletedEvent` is NOT changed in this story (that is Story 2.9, which depends on 2.6); a `// TODO(2.9)` comment is added at the event's confidence fields.

## Integration Verification

- **IV1:** `ExtractionOrchestrator.cs:377` contains `confidence = ocrResult.ConfidenceAvg / 100.0`; after migration this bridge must be removed and replaced with `ocrResult.Confidence.Value` directly.
- **IV2:** Static metadata extractors that hardcode `0.85` (`PdfMetadataExtractor.cs:623`) and `0.70` (`DocxMetadataExtractor.cs:386`) must use `Confidence.FromValue(0.85)` and `Confidence.FromValue(0.70)` respectively, with a `// TODO(2.7)` note that these are advisory placeholders pending the aggregation contract.
- **IV3:** The `ConfidenceGuard` in `Veriqan.Domain/Verification/ConfidenceGuard.cs:32` is a separate bounded context and must NOT be affected by this change.
- **IV4:** `ReconciliationOrchestrator.cs:227` currently reads `classificationResult.Confidence` as `int` and compares to `70`. After migration this must read `classificationResult.ClassificationConfidence.Value` and compare to `0.70` (or the bound config threshold per Story 2.8). This creates a hard dependency: Story 2.8 must be coordinated with or follow Story 2.6.
