# Story 2.7: Confidence Aggregation Contract and ADR

**Status:** Draft
**Epic:** 2 - Confidence Pipeline Hardening & Re-architecture
**Stage:** Cross-Stage (Architecture)
**Created:** 2026-06-25

---

## Story

**As a** system architect,
**I want** an explicit, recorded contract that defines what "document confidence" means and which pipeline signals compose the export gate decision,
**so that** the export hold/release decision is explainable, auditable, and maintainable as the pipeline evolves.

---

## Acceptance Criteria

1. The Architecture Decision Record `docs/architecture/adr/ADR-023-Unified-Confidence-Model.md` (already authored under this epic) is finalized/ratified, with its aggregation-contract section answering:
   - Which signals (quality / OCR / fusion / classification) enter the "document confidence" aggregate.
   - What the composition function is (min / weighted / classification-only / other).
   - Whether the quality signal (`ImageQualityLevel`, `QualityIndex`) is a gate input or purely advisory.
   - The rationale for any signals excluded from the gate.
2. `ExtractionOrchestrator.cs:403-408` is updated to either:
   - Populate `ExtractionMetadata.QualityIndex` from the `ImageQualityLevel` enum result (if the ADR decides quality IS a gate input), or
   - Carry an explicit code comment citing ADR-023 and stating the quality signal is advisory-only (if the ADR decides it is not a gate input).
3. `ReconciliationOrchestrator.EvaluateExportGate:214-258` is updated (or annotated) to reflect the ADR contract — each sub-gate must have a comment citing ADR-023 and its role in the contract.
4. If the ADR decides OCR or fusion confidence enters the gate numerically, the corresponding gate check is added to `EvaluateExportGate`; if excluded, a comment explains why.
5. The existing three sub-gate tests in `ReconciliationOrchestratorExportGateTests.cs` remain green; any new gate check added per AC4 is covered by a new test in the same file.
6. `dotnet build` 0/0.

---

## Integration Verification

- **IV1:** The ADR decision on quality must align with what `FusionExpedienteService.cs:301-304` does (it can read `ExtractionMetadata.QualityIndex` but the worker never sets it). Story 2.7 must either close that gap or formally declare it closed as advisory.
- **IV2:** If quality enters the gate, the `ImageQualityLevel` enum (`Domain/Enum/ImageQualityLevel.cs:10-16`) ordering must be re-verified: `Q3_Low=3`, `Q4_VeryLow=4`, `Pristine=5` is non-monotonic with naming. The ADR must address this.
- **IV3:** This ADR is a prerequisite for Story 2.8 (threshold config) — the ADR defines which thresholds exist; 2.8 binds them. These stories can be drafted in parallel but 2.8 must not be merged before ADR-023 is ratified.

## Dev Notes

### Inspection Evidence

Source: `docs/planning-artifacts/remediation/CONFIDENCE-PIPELINE-DEEP-INSPECTION-2026-06-25.md` §3.2, §3.4, §4.1, §5 T3.2

**Quality never gates export (§3.2):**
> "Quality → dropped. Fusion can read `ExtractionMetadata.QualityIndex` (`FusionExpedienteService.cs:301-304`) but the worker path **never sets it** (`ExtractionOrchestrator.cs:403-408` sets only `MeanConfidence`); the `Q3_Low` enum is never turned into a number."

**OCR and fusion never gate export (§3.2):**
> "Nothing combines the four numbers. There is no 'overall document confidence.' The export gate evaluates three independent sub-gates (`ReconciliationOrchestrator.EvaluateExportGate:214-258`); the fusion `0.83` is never compared to a threshold there."

**The gate sub-structure (§4.1):**

| Gate | Condition | Input | Hardcoded/Config |
|------|-----------|-------|------------------|
| 1 | `classificationResult.Confidence < 70` | `ClassificationResult.Confidence` int | hardcoded `:42` |
| 2 | `NextAction == ManualReviewRequired` | `FusionResult.NextAction` | toggle unbound |
| 3 | `ConflictingFields.Count > 0` | `FusionResult.ConflictingFields` | toggle unbound |

**What "fusion confidence" actually is (§3.5):**
> "`FieldFusionResult.Confidence` is set to `SourceReliability / maxReliability` (`FusionExpedienteService.cs:214,245`); `OverallConfidence` is the 70/30 weighted average of those (`:2501`). So `0.83` is a source-reliability figure, not a calibrated likelihood — worth knowing before any 'combine the confidences' design."

**The ImageQualityLevel non-monotonic ordering (§3.4 item 1):**
> "Quality enum never numerically combined; ordering is non-monotonic/undocumented (`Q3_Low=3`, `Q4_VeryLow=4`, `Pristine=5`) — `Domain/Enum/ImageQualityLevel.cs:10-16`."

The ADR must decide whether to fix the enum ordering or map it explicitly to a numeric scale before using it as a gate input.

**Hardening prescription (§5 T3.2):**
> "Define an explicit aggregation contract — *what is 'document confidence' and which signals compose it?* Decide whether the export hold should consider OCR/fusion/quality (today it ignores all three). Make quality actually flow (populate `QualityIndex`, `ExtractionOrchestrator.cs:403`) or formally declare it advisory."

### Change-Impact Tests (§4.4)

`ReconciliationOrchestratorExportGateTests.cs` lines 149/201/251/314/361/403 — these pin the existing three-gate behavior. Adding a fourth gate (per Option B or C) requires new test cases; the existing ones must not change semantics unless the gate contract changes.
