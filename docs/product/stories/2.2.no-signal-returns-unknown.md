# Story 2.2: No-Signal Result Returns Unknown (Not a Fake Real Type)

**Status:** Draft
**Epic:** 2 - Confidence Pipeline Hardening & Re-architecture
**Stage:** Stage 4 - Classification
**Created:** 2026-06-25

---

## Story

**As a** compliance analyst reviewing document classification results,
**I want** a document with no keyword matches to be labeled `Unknown`/`Unclassified` at confidence 0,
**so that** I am never misled into believing a document has been confidently classified when the classifier had no signal at all.

---

## Acceptance Criteria

1. `DetermineLevel1Category` (`FileClassifierService.cs:238-251`) returns an explicit `Unknown` or `Unclassified` category value (not `Aseguramiento` or any other real type) when all six category scores are tied at the no-match floor.
2. `CalculateConfidence` (`FileClassifierService.cs:205-236`) returns `0` (or a distinguished sentinel value) for an all-tied-at-floor result, not `10` or any numeric value that resembles a genuine confidence score.
3. A unit test `CalculateConfidence_AllCategoriesTiedAtFloor_ReturnsZeroConfidence` confirms that `combinedText = ""` (or text with no known keywords) produces `Confidence == 0`.
4. A unit test `DetermineLevel1Category_NoKeywordMatch_ReturnsUnknown` confirms the returned category is `Unknown`/`Unclassified`, not `Aseguramiento`.
5. All existing unit tests for `FileClassifierService` that exercise valid keyword-bearing inputs continue to pass without modification.
6. Story 2.1's new regression test (`IMSS-2023-171230` classifies as Aseguramiento ≥ 70) continues to pass, confirming that the Unknown guard is not triggered for real-signal documents.
7. `dotnet build` 0/0.

---

## Integration Verification

- **IV1:** The `ClassificationResult` returned by `IFileClassifier.ClassifyAsync` in the Unknown case must have a `Confidence` value that the export gate (`ReconciliationOrchestrator.cs:225-231`) correctly interprets as below-threshold — i.e. the gate still fires on Unknown documents, it simply does so with an honest signal.
- **IV2:** If `ClassificationLevel1` is an enum, `Unknown` or `Unclassified` must be a valid member with a non-zero ordinal that is clearly distinguishable from `Aseguramiento` (ordinal 0 / first-inserted); update any switch exhaustiveness checks.
- **IV3:** Downstream consumers of `ClassificationResult.Level1` (audit trail, export pipeline) must handle `Unknown` gracefully — do not throw on an unexpected enum value.

## Dev Notes

### Inspection Evidence

Source: `docs/planning-artifacts/remediation/CONFIDENCE-PIPELINE-DEEP-INSPECTION-2026-06-25.md` §2.4

**The arithmetic that produces `(Aseguramiento, 10)` from no signal:**

Keyword scoring assigns each of 6 categories: `90` (strong hit), `70` (weak hit), `10` (no hit) — `FileClassifierService.cs:85/89/93` etc.

With no keyword present, all six scores = 10. Then `CalculateConfidence` (`FileClassifierService.cs:205-236`):
- `maxScore = 10`
- `averageScore = 10`
- `scoreDifference = 10 − 0 = 10` (empty second set)
- `10 < 40` branch → `Math.Min(70, averageScore)` = **10**

And `DetermineLevel1Category` (`:238-251`) does `OrderByDescending(value).First()` over a dictionary whose **first inserted key is `Aseguramiento`** → on an all-tie it returns Aseguramiento.

**Why this is a correctness hazard (§2 Executive Verdict):**
> "Confidence 10 means *zero keywords matched*, not 'weak aseguramiento evidence.' So any no-signal document is labeled `(Aseguramiento, 10)` — a default type that *looks* like a real classification at a real-looking confidence."

**The fix the inspection prescribes (§5 T1.2):**
> "In `DetermineLevel1Category`/`CalculateConfidence` (`FileClassifierService.cs:205-251`), an all-tied-at-floor result must return an explicit `Unknown`/`Unclassified` (or confidence 0), **never `(Aseguramiento, 10)`**."

### Change-Impact Tests (§4.4)

`ReconciliationOrchestratorExportGateTests.cs` — line 149 uses confidence 50; line 201 uses 95; line 251 uses 30; line 314 uses 90; line 361; line 403. After this change, any test that previously exercised a no-signal path and expected `Aseguramiento` at `10` must be updated to expect `Unknown` at `0`.
