# Story 2.8: Single Source of Truth for Thresholds (Bound ExportGatePolicy Config)

**Status:** Draft
**Epic:** 2 - Confidence Pipeline Hardening & Re-architecture
**Stage:** Cross-Stage (Configuration)
**Created:** 2026-06-25

---

## Story

**As a** DevOps engineer deploying the Prisma pipeline,
**I want** all confidence thresholds to live in one bound configuration section (`ExportGatePolicy`) that I can override per environment,
**so that** I never have to search source code to find where `70` is hardcoded or reconcile disagreeing constants across files.

---

## Acceptance Criteria

1. The hardcoded literal `70` (classification confidence threshold) in `ReconciliationOrchestrator.cs:42` is removed and replaced by a read from the `ExportGatePolicy` configuration object.
2. The duplicate literal `70` (manual review flag threshold) in `ProcessingOrchestrator.cs:56` is removed and reads from the same `ExportGatePolicy` object or a shared constant that references it.
3. `ExportGatePolicy.cs` (which already has `SectionName = "ExportGatePolicy"` at `:28` but is never bound) is wired via `services.Configure<ExportGatePolicy>(configuration.GetSection(ExportGatePolicy.SectionName))` in both `Reconciliator Program.cs` (near line 157) and `Athena Program.cs` (near line 163).
4. An `appsettings.json` entry for `"ExportGatePolicy"` is added to both Reconciliator and Athena project `appsettings.json` files with the current default values (`ClassificationConfidenceThreshold: 70`, and the existing boolean toggles set to `true`).
5. The stray `< 80` threshold in `ManualReviewerService.cs:646-660` is either:
   - Unified with the `ExportGatePolicy.ClassificationConfidenceThreshold` (if the business intent is the same), or
   - Kept as a separate named constant (`ManualReviewLowConfidenceThreshold = 80`) with an XML comment explaining why it differs from the export gate threshold, and the discrepancy is documented in `ExportGatePolicy.cs`.
6. The fusion thresholds `ManualReviewThreshold = 0.70` (`FusionCoefficients.cs:136`) and `AutoProcessThreshold = 0.85` (`FusionCoefficients.cs:129`) are cross-referenced in `ExportGatePolicy.cs` (comment or property reference) to document the 0-1 vs 0-100 distinction and prevent future collision.
7. All §4.4 tests (`ReconciliationOrchestratorExportGateTests.cs`, `ProcessingOrchestratorTests.cs:541`) pass; any test that injected a hardcoded `70` comparison is updated to inject the threshold through `ExportGatePolicy`.
8. `dotnet build` 0/0.

## Integration Verification

- **IV1:** After Story 2.6 migrates `ClassificationResult.Confidence` to `Confidence.Value` (0–1 scale), the `ExportGatePolicy.ClassificationConfidenceThreshold` must also shift to `0.70` (not `70`) to stay consistent. This story should coordinate with Story 2.6 — either accept that value in both scales now and migrate in one step with 2.6, or keep as `70` (int) until 2.6 lands and then migrate both together.
- **IV2:** `ExportGatePolicy` toggle properties (`BlockOnLowConfidence`, `BlockOnFusionManualReviewRequired`, `BlockOnUnresolvedConflicts`) are already defined but are never read from config. Binding them must not change the default values (all `true`) so existing gate behavior is unchanged at startup with no config override.
- **IV3:** The two `Program.cs` composition roots (`Reconciliator` and `Athena`) must each inject `IOptions<ExportGatePolicy>` into `ReconciliationOrchestrator` (and/or `ProcessingOrchestrator`) constructors; the DI wiring must be consistent so integration tests that use `WebApplicationFactory` or worker-host test setup do not fail.

## Dev Notes

### Inspection Evidence

Source: `docs/planning-artifacts/remediation/CONFIDENCE-PIPELINE-DEEP-INSPECTION-2026-06-25.md` §4.2, §4.3, §5 T3.3

**Dead config (§4.2):**
> "`ExportGatePolicy` has a `SectionName = 'ExportGatePolicy'` (`:28`) and settable bools but is **never bound** — no `Configure<ExportGatePolicy>` / `GetSection` / `.Bind` anywhere, no `ExportGatePolicy` key in any appsettings. Both production sites construct the all-ON default (`ReconciliationOrchestrator.cs:88`, call sites `Reconciliator Program.cs:157`, `ProcessingOrchestrator.cs:116`). **The toggles can turn gates off but cannot change the `70`.**"

**All the competing threshold constants (§4.3):**
```
ReconciliationOrchestrator.cs:42    ClassificationConfidenceThreshold = 70   (gate)
ProcessingOrchestrator.cs:56        (duplicate literal 70)                    (flag)
ManualReviewerService.cs:646-660    < 80                                      (review category)
FusionCoefficients.cs:129           AutoProcessThreshold = 0.85               (fusion)
FusionCoefficients.cs:136           ManualReviewThreshold = 0.70              (fusion)
BulkProcessingService               75.0f                                     (unrelated)
DocxFieldExtractor                  0.3f                                      (field-level)
```
This story targets the first three (all classification/export-gate related). The last two rows are out of scope for this story.

**The 0.70-vs-70 collision (§3.4 item 7):**
> "`ManualReviewThreshold = 0.70` and `ClassificationConfidenceThreshold = 70` are the same intent in two units — impossible to keep in sync automatically."

After migration to `Confidence.Value` (0–1 scale, Story 2.6), the `ExportGatePolicy` threshold becomes `0.70` on the 0–1 scale, and the fusion `0.70` is the same number — they can be explicitly cross-referenced or even unified if the aggregation contract (Story 2.7) decides they represent the same gate.

**The hardening prescription (§5 T3.3):**
> "Single source of truth for thresholds. Promote the hardcoded `70` into bound `ExportGatePolicy` config (§4.2), de-duplicate the two `=70` constants and reconcile the stray `<80` (`ManualReviewerService.cs:646`) and fusion `0.70/0.85`. One config object, bound at both composition roots, covered by the §4.4 tests updated in lockstep."

### Change-Impact Tests (§4.4)

`ReconciliationOrchestratorExportGateTests.cs` lines 149/201/251/314/361/403 — currently inject confidence values directly. After this story, the orchestrator reads the threshold from `IOptions<ExportGatePolicy>`. Tests that use a real `ReconciliationOrchestrator` must provide an `ExportGatePolicy` option in their test setup (e.g. via `Options.Create(new ExportGatePolicy { ClassificationConfidenceThreshold = 70 })`).

`ProcessingOrchestratorTests.cs:541` — confidence 45 vs threshold 70 flag. Same update needed.

`FusionExpedienteServiceMutationTests.cs:236-281` — tests `0.85/0.70` fusion thresholds. These read from `FusionCoefficients` directly; this story does not change those, only cross-references them.
