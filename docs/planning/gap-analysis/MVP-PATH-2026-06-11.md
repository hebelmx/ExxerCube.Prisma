## Appendix A — Item 1.3 (real Ember in workers) sub-plan  *(investigated 2026-06-11; deferred)*

**Why it's not a quick win (finding from this session):** `ExxerHub<T>` (IndFusion.Ember) is a **hosted SignalR `Hub`** — the UI hosts `/processingHub` via `app.MapHub<ProcessingHub>("/processingHub")` (`Web.UI/Program.cs:117`) and registers `IExxerHub<DomainEvent> → ProcessingHub`. `IExxerHub<T>.SendToAllAsync` is the **server-side broadcast** abstraction (broadcast to clients connected to *this* hub). So "real Ember in the Orion worker" is **not a drop-in swap** of `StubExxerHub` — it forces a **topology decision**:

- **Option A — worker hosts its own hub:** Orion exposes a hub endpoint; the UI (and other processes) connect to Orion as *clients*. Inverts the current direction; if nothing connects, the "real" hub has **zero subscribers** — no better than the stub but misleadingly "done."
- **Option B — worker is a SignalR *client*:** Orion holds a `HubConnection` to the UI's `/processingHub` and relays events (e.g. `InvokeAsync("BroadcastDomainEvent", …)`). A client-side `IExxerHub<DocumentDownloadedEvent>` impl wrapping the connection. Needs the UI hub URL (config), event serialization, and reconnect handling. Check whether `IndFusion.Ember` ships a client wrapper before hand-rolling.
- **Note on server-side use:** broadcasting from a background service via a `Hub` instance resolved from DI doesn't work in raw SignalR (`Clients` is per-connection) — Ember's `ExxerHub<T>` must wrap `IHubContext` internally; confirm how before assuming DI resolution broadcasts.

**Why deferred:** this is genuinely **M-sized** and **coupled to item 1.4** (the 3-process split). The hub topology (who hosts, who connects) should be decided *as part of* the Downloader/Extractor/Reconciliator design, not bolted on now — otherwise it's rework. **Recommendation:** fold 1.3 into the 1.4 design session; pick Option B (workers as clients to a central hub) unless 1.4 argues for a hub-per-process mesh. Until then `StubExxerHub` stays, clearly labelled.

**Pre-reqs to resolve in that session:** (1) inspect the `IndFusion.Ember` package for a client-side hub abstraction; (2) decide central-hub vs mesh; (3) where the hub URL/config lives for each worker; (4) how this rides the security boundary (events/handoffs, not shared raw access — MVP A4/A5).
