## 1. Executive Summary

Veriqan VEC is a substantial, well-architected engine whose **unit layer is green and whose core computation logic is genuine** (real PdfPig extraction, real arithmetic identities, real abstain-safety discipline, real EF Core persistence schema). However, at the full-production bar the system is **not deployable, not end-to-end proven, and not safe on several real input classes**.

The honest state in twenty lines:

**What is built and unit-green:**  
The validation/verdict/extraction/reporting *components* are real — 468 validation tests green, 37 orchestration tests green (on synthetic fixtures), real AES-256 persistence schema, real PdfPig extraction, real PdfSharp marked-PDF generation, real SMTP alerting, real EF Core migrations. The abstain-safety discipline (InsufficientData never escalates to RED) is structurally sound and survives adversarial review.

**What is not proven end-to-end:**  
Nothing has ever been demonstrated on a real CONDUSEF statement. The only corpus is 3 KnownSynthetic non-compliant PDF fixtures. Zero KnownGood specimens exist. The calibration harness exists but its FPR/DR computations are vacuous. All thresholds are spec-derived or guessed, never measured.

**What has no deployable surface:**  
The Veriqan Worker (`Program.cs`, 21 lines) is an orphaned health-check shell. It has no ingestion entry point, no appsettings.json, no Dockerfile, no observability backend, no authn/authz. All persistence defaults to in-memory. The report (marked PDF) and notify (email alert) stages are DI-wired but never called by the pipeline. The pipeline itself is reachable only from test harnesses.

**Cardinal-rule violations latent on real inputs:**  
(1) Scanned/image-only PDF: `BuildAllAbsent()` emits mandatory sections as `IsApplicable=true, IsPresent=false` → `MandatorySectionsPresenceRule` FAILs all → **false RED** on a compliant scanned statement. (2) §20 saldo-a-favor sign: if a bank prints saldo-a-favor as a negative signed amount, the rule adds instead of subtracts → false FAIL beyond tolerance → **false RED**. (3) §16 column-map: 9-column index is a self-declared guess → false PASS or false FAIL on a real §16 with different column order. (4) Missing reference bundle → BLOCKED on a good statement (as-shipped Worker state). (5) Card number rendered in image/header graphic → CL-34 **false FAIL** on every page.

**Non-engineering critical-path unlocks (not engineering tasks):**  
E13 buyer gate (issue #17, open) and real CONDUSEF corpus acquisition block full calibrated production.

**Distance to full production:** Large. Minimum deployable composition (one real statement end-to-end) requires ~8 focused engineering items. Full production requires those plus corpus calibration, cardinal-rule fixes, full persistence wiring, security hardening, E13 product half (business-gated), and LFPDPPP compliance design (business-gated).
