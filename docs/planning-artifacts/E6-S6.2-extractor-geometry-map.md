# E6.S6.2 — Extractor positional-geometry map (design input)

**Purpose:** ground-truth reference for the synthetic estado-de-cuenta generator. The synthetic
layout MUST place tokens where `PdfPigStatementFieldExtractor` expects them, or the positional
extractor abstains even though the field is present (the trap that killed E2.3).

**Source:** `Prisma/Code/Src/CSharp/02 Infrastructure/Veriqan.Infrastructure.Extraction/PdfPigStatementFieldExtractor.cs`
(read 2026-07-06). Coordinate system = **PDF points, origin bottom-left** (PdfPig `BoundingBox.Bottom`
grows upward).

> ⚠️ **PAGE-SIZE CORRECTION (verified 2026-07-06):** the **Dummie-VEC** fixtures
> (`Prisma/Fixtures/PRP2/01+Dummie+VEC+jul_ago+20252.pdf` etc.) — the layout the synthetic generator
> replicates and whose TASA/CAT/RESUMEN are ALREADY asserted `Extracted` in the green suite

> body fs ≈ 8. The **612 × 792 (US Letter)** figure below belongs to the **real `good.pdf` Banamex**

> Dummie-VEC-calibrated and correct; only the page-size header was wrong. The canonical corrected
> placement table lives in `E6-S6.2-synthetic-generator-design.md`.

> **KEY INSIGHT:** the extractor's per-field methods are calibrated (see their code comments) to a
> **"Dummie VEC" synthetic layout** with the canonical Y-coords below — NOT to the real `good.pdf`
> Banamex layout. Each field method has a *primary* pass on the Dummie-VEC geometry plus *fallback*
> passes for the real Banamex left-column layout. **The synthetic generator should replicate the
> Dummie-VEC geometry** — that is where TASA/CAT, RESUMEN, NIVEL DE USO all resolve cleanly (the
> fields the real anonymized `good.pdf` cannot supply because their values aren't in its text layer).

**Period/summary extraction is PAGE-1-ONLY** (`:554-560` comment): including page-2 words corrupts
band grouping because PdfPig resets Y per page. So all verdict-gating summary fields must be on page 1.

## Amount parsing
`FindAmountInBand` / `FindAmountInBandSplitDollar` — the latter handles a separate `$` glyph token then the number. `ParsePercent` :2176 for `NN.NN%`. `AmountNumberFormatSession` learns the locale (`,` vs `.` decimal) from the doc.

## What the real `good.pdf` CANNOT supply (why synthetic is needed)
Confirmed by PdfPig dump of `Prisma/Fixtures/PRP2/demo/good.pdf` page 1:
- **TASA/CAT values** — no uppercase TASA/CAT token with Bottom<350; real rate is split across footer tokens (`29` + `.72%`) in the mag-stripe legend at Bottom≈5. Not recoverable.
- **Fecha límite de pago** — no such 4-word label band (only "Fecha de corte").
- **RESUMEN / NIVEL DE USO / DESGLOSE literal headings** — do not exist; the real doc uses different phrasing/geometry (left-column projection blocks), and the movements table isn't populated on page 1 in this low-activity sample.

**Design implication:** the synthetic generator replicating the **Dummie-VEC geometry** above will make
these fields resolve **positionally with the existing extractor unchanged**, against a god's-eye manifest.

> **Scope honesty (do NOT overclaim):** this proves the **Dummie-VEC layout variant only** — a
