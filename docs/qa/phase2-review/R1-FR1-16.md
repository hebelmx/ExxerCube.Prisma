## Notes / Anomalies

1. **PDF page-iteration off-by-one (FR6 defect — `e2e-rerun.log` line 288):**
   `ArgumentOutOfRangeException — The page number must be between 0 and 2. The PDF has 3 pages in total.`
   The log records that page 3 was actually converted before the warning fires (line 287 shows 378,310 bytes produced). The warning fires on a redundant fourth loop iteration, i.e., the loop runs `page = 0..3` when it should stop at `page = 0..2`. This is a fencepost error in the PDF rasterization loop. The pipeline continued using page 1, so functional impact this run was nil, but it will truncate or warn on every 3-page PDF.

2. **Excel (DatosCargaOficio) export event never emitted (FR18 — out of scope FR1-16, but related to FR15 pipeline):**
   `e2e-rerun.log` line 426: `Starting DatosCargaOficio layout generation` was logged immediately after SIRO XML success, but no completion log and no `ExportCompletedEvent(DatosCargaOficioXlsx)` arrived within the 60-second window. The test failed here (`MaxFidelityGateFullPipelineE2ETests.cs:141`). The Excel layout generator (`DatosCargaOficioLayoutGenerator`) started but did not complete or emit its event. This is a live pipeline defect — the layout generation either hangs or silently fails. Worth investigating: the generator took from 14:48:49 to at least 14:49:36 (nearly 47 seconds) before the shutdown log appeared.

3. **SLA records not created for processed case (FR12/FR13):**
   Despite the live pipeline processing case `UIF-2025-366293` through all five stages, no `INSERT INTO [SLAStatus]` was observed in the logs. The SLA background service polled repeatedly but found `Retrieved 0 active cases` throughout. This indicates the pipeline does not create an SLA record upon case intake — the SLA table is polled but never written to by the main flow in this run.

4. **Identity resolution and legal directive classification not visible in pipeline log (FR10/FR11):**
   Both `PersonIdentityResolverService` and `LegalDirectiveClassifierService` have implementations and test suites, but no log entries from these services appear in the live pipeline trace. Their DI registration in the Reconciliator's `Program.cs` is not visible in lines read — they may not be wired in the E2E composition root, or they run without logging at the stages observed.

5. **Authenticated UI routes only — five screens redirect to login:**
   Routes `/processing`, `/review`, `/export`, `/audit`, `/sla` all produce identical 4,254-byte responses consistent with a login redirect. UI behaviour for authenticated users (FR14 manual review interface, FR15 export management) cannot be assessed from unauthenticated HTTP probes alone.

6. **Level-1 classification confidence = 10 (very low):**
   The live run produced `Confidence: 10` for the `Aseguramiento` classification (line 395 warning). This is within the expected range for the deterministic classifier on a synthetic test document, and the system correctly flagged it for manual review. Not a defect — the threshold logic works — but the accuracy of deterministic classification on real documents requires human validation.

7. **Web UI health = 503 (degraded, expected):**
   `GET /health` returns 503 because `appsettings.json` hardcodes `Server=DESKTOP-FB2ES22\SQL2022`. This is documented expected behaviour per CLAUDE.md. `GET /` returns 200; the MudBlazor shell renders. No blocking issue for this review scope.
