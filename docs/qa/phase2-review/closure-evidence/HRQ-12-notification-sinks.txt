## CONCLUSION (characterized 2026-06-20)

FR31 = "do NOT notify the involved/regulated client unless legal directive allows."

Findings characterized:
- EMAIL: the only Prisma email sender is `Web.UI/Components/Account/IdentityNoOpEmailSender.cs`
  — a NO-OP (ASP.NET Identity account scaffolding that sends nothing). The other email code
  (`Veriqan.Application/Ports/IEmailSender.cs`, `Veriqan.Infrastructure.Reporting/SmtpEmailSender.cs`,
  `VecAlertService.cs`) belongs to the **Veriqan** product, NOT the Prisma compliance pipeline.
  ⇒ No Prisma path emails the regulated client.
- SMS/Twilio: none.
- SLACK/WEBHOOK: 0 real integrations. All 6 "slack" hits are the substring in `HorizLeftSlack`
  (a geometry constant in Veriqan visual rules). False positives.
- SIGNALR (`Clients.All`/`Group`): ProcessingHub, SignalRIngestionBroadcaster,
  SignalRReconciliationBroadcaster, HubContextDomainEventBroadcaster broadcast processing/SLA/
  domain-event status to **connected operator dashboards** (the Web UI), NOT to the investigated client.

VERDICT (HRQ-12 = A): No component notifies a party OUTSIDE the system operators. FR31 is
**satisfied by absence** of any client-facing notification channel. ⇒ CRIT-1 downgrades from
Critical to a low-risk note + a regression guard (a test that fails if an external-notification
sink is introduced without a legal-directive gate).

NUANCE / follow-up (security, not FR31): SignalR uses `Clients.All`, so status is broadcast to
ALL connected clients. Combined with the unauthenticated dashboard exposure (HIGH-2/HIGH-3), this
means operational data reaches any connected (possibly unauthenticated) client. Once Identity is
enforced, broadcasts should target authenticated operator groups, not `Clients.All`. Tracked with
the auth fixes (G-H2/G-H3), not FR31.
