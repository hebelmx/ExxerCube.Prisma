# Task: Extract Project-Agnostic Architectural & Solution Guidelines

## Objective:
Analyze the provided codebase to extract and document detailed architectural patterns, technology stack choices, coding style conventions, and solution guidelines. The primary goal is to produce a comprehensive report that can serve as a highly opinionated but project-agnostic guide for a new software project.

## Key Requirements for the Output:
1.  **Detailed Architecture:** Identify and describe the main architectural components, their responsibilities, and how they interact. This should cover logical and physical architecture where discernible.
2.  **Technology Stack:** Clearly enumerate and justify the key technologies, frameworks, and libraries used within the project. Provide insights into why these choices might have been made and their typical usage patterns.
3.  **Coding Style & Conventions:** Document prominent coding style guides, naming conventions, directory structures, and any other established development practices observed in the codebase.
4.  **Solution Guidelines:** Derive general "best practices" or "solution patterns" from the existing code that are applicable across different projects. This should include common approaches to error handling, data management, security considerations, and deployment strategies.
5.  **Project-Agnostic:** The output document should focus on principles and patterns that are transferable. Avoid specific business logic or domain-specific details of the current repository.
6.  **Highly Opinionated:** The generated guidelines should reflect a strong stance based on the observed patterns. For example, if a specific ORM is used consistently, the guideline should confidently recommend that ORM and explain its typical application.
7.  **Format:** The output should be a well-structured Markdown document, easy to read and understand.

## Deliverable:
A Markdown file containing the extracted architectural and solution guidelines, adhering to all the above requirements.
